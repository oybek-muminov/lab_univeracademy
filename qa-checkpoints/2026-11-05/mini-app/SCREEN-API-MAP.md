## Umumiy auth va xato talablari

- Faqat Backend kelishgan HTTP kontrakti/generated client. `StudentPort` proyeksiyalari wire schema yoki qo‘lda parallel HTTP client emas.
- `POST /auth/refresh`, `POST /auth/logout` draftda mavjud, ammo bu checkpointda real session lifecycle, token persistence yoki refresh retry kodi yo‘q. Opaque StudentSession StaffJWT bilan almashtirilmaydi. Auth/revocation holatida kerakli qayta kirish yo‘li Backend bilan kelishiladi.
- `REVISION_CONFLICT` → authoritative GET → farqni saqlab, o‘quvchining aniq qarori. `ATTEMPT_SUPERSEDED` → current Series/generationni qayta o‘qish va eski navbatni bekor qilish. `ATTEMPT_EXPIRED` → authoritative terminal/result read; kech save qayta yuborilmaydi.
- `401/403`, concealed `404`, validation `422`, `429`/Retry-After va vaqtinchalik `5xx`ning aniq UX mappingi hali yozilmagan. Mock barcha xatoni bitta umumiy xavfsiz xabar bilan beradi; bu real error handling tugallanganini anglatmaydi. Sonli retry intervali/polling siyosati tanlanmagan.
- Biror mutation javobi noaniq bo‘lsa UI muvaffaqiyat ko‘rsatmaydi. Server ruxsat, vaqt, revision, generation, idempotency, javoblar va ball uchun authoritative qoladi.
